# 领域规则

## Stage 0 已固定

- 输入显式区分公历和农历，不允许靠文本猜测。
- 农历闰月由独立布尔字段表达；只有进入 Tyme4j 适配器时才转换为负月份，领域模型和
  UI 不保存负月份。
- 计算快照保留原始历法输入，并同时记录标准公历和标准农历转换结果；旧快照缺少该字段
  时按 `null` 读取，不伪造历史证据。
- 性别字段当前只服务于顺逆排运，命名为 `SexForFortuneDirection`。
- 计算配置必须保存 `engineVersion` 与 `ruleVersion`。
- 结果必须回带归一化输入、计算配置、引擎证据及警告。
- 新建和编辑命例必须填写出生地区；经纬度允许成对留空，手工填写时记录
  `CoordinateSource.USER_ENTERED`。旧数据缺少地区或坐标来源时仍可读取，不伪造来源。
- 时区必须使用 IANA `ZoneId`。唯一时区解析入口在领域层，并且只使用标准公历墙上时间
  解析历史 offset；农历输入必须先转换为标准公历，再进入同一解析入口。
- 普通本地时刻自动固化 UTC offset 与平台 tzdb 版本；夏令时回拨重叠时刻必须由用户从
  有效 offset 中明确选择，跳时产生的不存在时刻必须拒绝，不能自动向前平移。
- `BaziCase.birthInput` 和 `CalculationResult.normalizedInput` 必须保存同一份解析后时区
  证据；重复检查也使用解析后输入。原始历法及墙上时间仍保持不变。
- 真太阳时由 `TrueSolarTimeCalculator` 唯一入口计算，当前实现固定为
  `nrel-spa-2008+solarpositioning-2.0.12-v1`。启用时经纬度必须同时存在，并保存原始
  民用时、经度平太阳时校正、均时差校正、总校正、最终真太阳时、跨日/跨时辰标记和
  算法版本；关闭时不得生成伪证据。
- 真太阳时作用规则暂定为
  `CIVIL_YEAR_MONTH_TRUE_SOLAR_DAY_HOUR_PROVISIONAL_V1`：年柱、月柱保留原始民用时
  Tyme 口径，日柱、时柱按真太阳时当地日界和时辰边界。问真跨日、跨时辰和节气边界
  样本共同验收前，配置、页面和警告都不得移除 `PROVISIONAL` 语义。Tyme4j
  `SolarTime` 只是公历时间类型，不得误称为真太阳时。
- `BirthInput.useTrueSolarTime` 与 `CalculationProfile.solarTimeMode` 必须一致；
  不一致、缺经纬度、缺解析后 offset 或超出 SPA 1..6000 年范围时明确失败。
- 基础排盘明细必须与最终采用的四柱在同一 `CalculationResult` 中一次生成，页面、列表和
  数据层不得重新推导。生肖取最终年柱地支，因而沿用立春换年；西方星座取标准公历日期。
- 四柱明细固定包含主星、天干地支五行、藏干及副星、日主十二长生、自坐、旬空和纳音；
  十神统一以日干为参照，日柱主星在页面按性别显示“元男/元女”，不改写底层计算值。
- 节气结果保存该标准公历时刻之前/当下最近节气与下一节气的精确时刻及“节/气”类型。
  `basicChartDetails` 对旧快照兼容为空；缺失时只显示未记录，不根据旧四柱补造历史证据。
- 问真基本资料使用的“前一节/后一节”与相邻二十四节气分开保存；前后节只接受
  `SolarTermType.JIE`，旧快照缺失时保持为空。胎元、胎息、命宫、身宫和前后节截图字段
  只在正式提交后从同一已采用快照生成计算值，不由页面或解析器重算。
- 计算档案差异必须先比较规范化出生输入与六项规则配置，再比较引擎/规则版本和确定性
  结果。输入或口径变化时不得归因于引擎升级；历史快照只读保留，不改写旧结果。
- `WenzhenSourceFidelityContract` 列出的星宿、命卦、五行/党派比例、日主/阴阳属性、
  自定旺衰/格局及四柱神煞不是本机算法真值。它们可被提取、修正和采用为来源记录，但
  `calculatedValue` 与 `consistencyConfidence` 必须保持为空；百分比只允许 0–100。
- 默认使用精确立春换年、交节瞬间换月和 Tyme4j 默认 23:00 换日；命例也可显式选择
  “晚子时日柱算当天”。子时规则属于版本化 `CalculationProfile`，创建、编辑、候选盘、
  即时排盘和已采用快照必须沿同一链路保存，不得读取或改写 Tyme4j 全局八字 provider。
- 专业流运按用户输入的观察日期与时分计算流年、流月、流日、流时：流年按精确立春，
  流月只在十二“节”切换而不在十二“气”切换，流日按命例子时规则。观察时刻当前明确
  解释为民用时，不对观察地点额外做真太阳时校正。
- 大运至少输出起运时间、顺逆、起始年龄和前八步大运。
- `FortuneStart.endAt` 是童限结束、开始起运的精确公历时间；页面称为“精确交运时间”。
  起运年龄必须保留年、月、日、时、分，前八步大运逐步展示干支、起止年龄和起止年份，
  不允许只显示干支摘要。
- 即时排盘与保存必须复用同一表单校验、`CalculationProfile` 和 `BaziEngine` 调用链。
  即时排盘允许别名为空，不执行重复候选查询且绝不调用仓储写入；修改任一输入即清除旧
  预览，异步返回的过期结果不得覆盖新输入或离开的页面。

## Stage 1 数据合同

- `ABSENT` 表示来源未提供，`CLEARED` 表示用户明确清空，二者不能合并为空字符串。
- 命例稳定 ID 重复且没有修订号时返回“已存在”，不能覆盖。
- 更新必须携带期望修订号；旧修订返回冲突并保留现有数据。
- 反馈、点评、事件、快照、附件和字段证据都保存明确顺序。
- 文本记录和关键事件的新增、修改、删除都追加不可覆盖的版本；旧库首次修改或删除前
  先补建当前值基线，删除当前条目不删除其历史。
- 分析记录使用综合、性格、事业、财运、感情、健康、学业、家庭、其他九个统一分类；
  非分析记录不得携带分析分类，旧分析缺失分类时按“综合”展示。
- 关键事件标题可空但不得保存空白文本，最长 80 字；类别使用综合、学业、事业、财运、
  感情、家庭、健康、其他八类，旧数据缺失类别时按“综合”读取。
- 截图来源值、软件计算值和用户采用值分别保存。
- 专业细盘截图只有在同一表头行可靠覆盖流时、流日、流月、流年、大运、年柱、月柱、
  日柱、时柱九列时才拆分干支；缺列时不得按位置猜测。OCR 合并块只按其原边界框等比例
  拆分，观察时刻与九列值默认均不采用。
- 专业细盘正式提交必须继续以出生资料复算四柱作为硬门禁；随后按截图观察时刻复算流柱
  和当前大运，把本机值写入 `calculatedValue` 并逐字段记录一致/不一致。来源原文、
  规范值和采用值均不得被复算覆盖；P2 复算失败不得放宽四柱门禁或伪造一致性。
- 基本排盘正式提交后，按同一计算快照对照生肖、星座，以及四柱的主星、藏干、副星、
  星运、自坐、空亡和纳音；日柱主星按问真展示语义使用“元男/元女”。神煞算法未接入
  前只保留来源证据，`calculatedValue` 与一致性必须为空。
- 通用诊断包只汇总 App/Schema 版本、去身份化页面类型、忙闲状态、稳定错误码、截图
  会话状态/计数/解析器版本及有界诊断 ID。命例 ID、姓名、出生资料、OCR 原文、文件名、
  路径、URI、密码、哈希和附件内容一律不得进入诊断文本；没有稳定错误码时只记录
  `PRESENT_REDACTED`。
- 附件必须使用 App 私有根目录下的安全相对路径，并记录字节数和 SHA-256。
- 旧空库恢复入口仍要求空数据库和空附件目录；Stage 3B 逐例恢复必须由完整显式计划驱动，
  不允许无范围覆盖。
- 完整备份密码模式必须生成独立 v1 二进制容器，不能生成冒充加密的明文 ZIP。
- 完整 ZIP 未加密导出必须显式确认会包含全部敏感资料与附件；Android 系统文件入口只提供
  流，仍只能由 `CaseBackupService` 生成和解释备份。
- 完整 ZIP 预览只在私有临时区安全展开，校验路径、数量、展开上限、每文件哈希、领域引用
  与附件元数据后清理；预览不得检查空库条件、写数据库或开放恢复快捷入口。
- 完整备份通过全部文件校验后，逐命例合并稳定 ID 已存在、出生输入相同和四柱相同候选；
  候选必须包含本地 revision 与回收站状态，供提交前判断预演是否过期。预览本身不产生
  默认恢复决策，不写数据库或附件。
- 完整恢复计划必须覆盖全部来源且每例恰有一个显式决策。无冲突命例只能按原 ID 导入或
  跳过；冲突命例不得直接导入。保留两份必须确有冲突，范围合并必须选择当前活动候选及
  至少一个模块或来源字段。任何候选、revision 或回收站状态变化都使预览过期。
- 批量恢复 UI 不得替用户生成默认决策；进入范围合并后至少选择一个当前可追加模块或
  “采用来源”字段才能确认。界面中的“检查恢复方案”只产生零写入计划，不得伪装成恢复。
- 完整备份逐例预览必须绑定完整 `BaziCase` 来源聚合，而不是只绑定别名、出生输入和四柱；
  记录、历史、事件、快照、附件、字段证据、分组和标签均参与计划身份及后续提交复核。
- 完整恢复执行前必须重新认证同一明文或密码备份，并比较 manifest、文件数量和完整来源
  聚合；任何差异返回 `SOURCE_CHANGED_AFTER_PREVIEW`，不得沿用旧计划写入。
- 按原 ID 导入保留来源稳定身份；保留两份重建命例及全部子项 ID 并记录来源 ID；范围合并
  必须复用单命例的同一去重和字段采用语义。
- 范围合并选择记录或事件模块时，只复制经过内容去重后实际新增条目引用的来源附件；同一
  来源附件被记录、历史和事件共同引用时只重建一次 ID。目标既有附件和字段证据不得改写，
  未被所选新增内容引用的附件不得顺带导入。
- 导入附件必须复制到本次恢复的专属暂存目录，核对大小和 SHA-256 后原子切换到专属最终
  目录；数据库写入必须位于同一 Room 事务，失败时不得删除或覆盖既有附件。
- 附件切换前后必须持久化有界恢复日志。新命例记录提交后载荷，范围合并还必须同时记录
  目标提交前载荷。启动时仅在全部命例处于提交前状态时自动回收本次文件，或在全部命例
  处于提交后载荷且附件完全一致时确认提交；部分状态或不一致必须保留现场并提示人工检查。
- 完整备份密码容器固定使用 PBKDF2-HMAC-SHA256 600,000 次、16 字节随机盐与
  AES-256-GCM（12 字节随机 nonce、128 位认证标签），ZIP 流直接进入加密流；导入只
  接受 100,000～2,000,000 次 KDF，认证成功后才把临时 ZIP 交给原校验链。
- 单命例 JSON v1 使用完整 `BaziCase`、格式/App/数据库版本、ISO 导出时间、附件模式和
  规范载荷 SHA-256；预览限制 16 MiB，未知版本、非法引用或哈希不一致时零写入拒绝。
- 单命例明文导出必须显式确认敏感数据风险；轻量 JSON 固定为 `REFERENCES_ONLY`，
  不能把附件引用当作图片二进制已随文件导出。存在附件引用的 JSON 必须禁止提交。
- `.nfbcase` 命例包格式版本为 1，固定包含 `manifest.json`、`case.json` 和编号附件条目；
  manifest 必须绑定命例文档及每个附件的稳定 ID、ZIP 路径、字节数和 SHA-256。预览只在
  私有临时区展开，并限制条目数、单条目大小、总展开量和安全相对路径。
- 命例包提交必须重新打开同一来源并比较规范 manifest 与命例文档身份；所有来源附件必须
  在写库前再次通过大小、SHA-256 和引用闭包校验。保留两份或范围合并必须为新增附件生成
  新 ID 和事务专属路径，并重写记录、历史、事件及字段证据引用。
- 命例包附件提交复用共享恢复日志、`.restore-staging/<transactionId>` 暂存、专属最终
  目录和 Room 事务；失败只清理本事务新文件，启动恢复按提交前/后完整载荷收尾。
- 单命例密码容器版本为 1，导出固定使用 PBKDF2-HMAC-SHA256 600,000 次、16 字节随机盐
  与 AES-256-GCM（12 字节随机 nonce、128 位认证标签）；算法和迭代次数进入 AAD。
- 单命例导入只接受 100,000～2,000,000 次 PBKDF2，避免弱参数降级或恶意超量计算；
  无密码返回 `PASSWORD_REQUIRED`，错误密码、篡改或不受支持参数统一返回
  `DECRYPTION_FAILED`，解密成功后仍执行原格式、Schema、载荷哈希和领域校验。
- 命例包密码容器版本为 1，使用独立 magic/type 与参数 AAD；ZIP 流直接进入
  PBKDF2-HMAC-SHA256 600,000 次派生的 AES-256-GCM 加密流，不把整包读入内存。提交时
  必须再次输入密码，不得复用预览密码。
- 密码和可恢复密钥不得写入文件、Room、日志或 ViewModel 持久状态；服务使用调用方提供的
  临时密码，内部副本使用后清零。完整备份、单命例 JSON 与命例包密码容器相互独立。
- Android 创建/打开文档只负责提供流；JSON 由 `SingleCaseExchangeService` 解释，
  命例包由 `SingleCaseBundleService` 解释，页面不得直接解析或保存协议内容。
- 单命例导入分成零写入预览和提交两阶段；提交前重新查询冲突，候选变化时拒绝。
- “保留两份”必须生成全新的命例与子项 ID、记录 `copiedFromCaseId`，并通过仓储事务
  创建；“跳过”不得调用保存。
- 模块合并只追加来源独有快照、记录/历史、事件/历史、分组和标签；新增子项重建 ID，
  相同内容不重复追加，来源快照默认不改变采用状态。
- 标量差异默认保留本地，只有用户逐字段明确选择来源才替换；方案绑定目标 revision 和
  规范载荷哈希，任一目标事实变化都必须重新生成差异。
- 回收站命例不能直接作为合并目标，必须先恢复；合并不得隐式恢复或改变删除状态。
- `REFERENCES_ONLY` 文件存在附件引用时不得提交，直到附件二进制与事务恢复能力落地。

## 当前明确不支持

- 在线地点搜索、自动定位、行政区到时区/经纬度自动映射；
- 多引擎裁决；
- 问真截图 OCR 与字段纠错；
- 真实案例导入。

调用者请求尚未支持的口径时，适配器必须明确失败，不能静默降级为公历民用时。

## 时间语义

出生时间保留到秒；`timePrecision` 表示原始材料的可信粒度。当前计算仍需要完整时间，
但不得因为填入默认秒数就把来源精度伪装为“精确到秒”。时区解析只证明该本地时间对应
的历史 UTC offset；原始墙上时间、绝对时刻口径与真太阳时校正证据分别保存，任何一层都
不得覆盖另一层。

- 时间精度由用户显式选择，不再根据秒数是否为 0 猜测；支持精确到秒、精确到分钟、
  大约时间、只知小时、只知时辰和时辰未知。
- 精确到分钟和大约时间要求秒为 0；只知小时/时辰要求分秒为 0。时辰未知不得生成唯一
  命盘，必须进入候选时间流程。
- 时间来源独立记录为本人、家人、出生证明、问真截图、其他资料或未说明，并可附 500 字
  以内来源说明。旧数据缺失来源类型时按“未说明”读取，不反推。

## 命例生命周期

- 用户删除整例时只设置 `deletedAt` 并进入回收站，不删除聚合子项或物理附件。
- 回收站命例不出现在活动列表、不更新最近查看，恢复后继续使用原稳定 ID 和历史。
- 当前不自动清空回收站；永久物理清理必须另行定义备份、附件引用和确认边界。
- 命例复制生成新的稳定 ID 和快照 ID，保留出生资料、分类和计算结果；记录、事件、
  来源附件和字段证据不复制，并保存 `copiedFromCaseId`。
- 重复候选以“出生时间与性别相同”和“已采用四柱相同”分别给出理由；候选可以来自
  活动列表或回收站。系统不得自动合并、覆盖或恢复，只有用户明确确认后才保留两份。
