## 本增量实现

- 详情页新增“导出单命例 JSON”，先确认未加密敏感数据风险和附件仅引用限制；
- `CreateDocument(application/json)` 使用规范文件名创建用户可访问文件；
- 列表页新增“导入预览”，通过 `OpenDocument` 读取 JSON，不申请宽泛存储权限；
- ViewModel 在 IO 调度器打开/关闭流，只调用 `SingleCaseExchangeService`，页面不解析协议；
- 预览弹窗显示来源 App/Schema/时间、记录/事件/历史/附件计数及冲突候选理由；
- 预览是第一阶段零写入；提交前重新查询冲突，预览过期则拒绝并要求重新预览；
- “保留两份”重建命例、记录、历史、事件、快照、分组和标签 ID，并记录来源命例 ID；
- “跳过”明确零写入；带附件引用的 JSON 因没有图片二进制而禁用提交；
- 冲突候选可选择活动目标生成范围化差异；回收站目标必须先恢复；
- 模块合并只追加来源独有的计算快照、文本记录/历史、事件/历史、分组和标签；
- 逐字段覆盖别名、姓名、来源、出生输入与性别口径、五类资料、收藏和置顶；
- 所有字段默认保留本地，只有明确“采用来源”的差异会替换；目标任一事实变化即拒绝；
- 来源计算快照追加为未采用，不会静默改变当前采用盘；相同内容去重且子项重建 ID；
- 单命例密码容器版本 1 使用 PBKDF2-HMAC-SHA256 600,000 次、16 字节随机盐和
  AES-256-GCM（12 字节随机 nonce、128 位认证标签），关键参数进入 AAD；
- 导入只接受 100,000～2,000,000 次 KDF 迭代；无密码单独提示，错误密码、篡改或
  不受支持参数统一安全拒绝，解密后继续执行原格式、Schema、哈希和领域校验；
- 密码不会写入文件、Room 或持久状态；服务与 ViewModel 的私有字符数组用后清零；
- 明文导出风险确认继续保留，单命例与完整备份使用相互独立的版本化密码容器；
- 列表页新增“导出完整备份”和“检查完整备份”，使用系统创建/打开文档，不申请宽泛权限；
- 完整 ZIP 导出确认明确包含全部命例、敏感记录、版本历史和来源图片附件；
- 完整 ZIP 预览在私有临时区校验路径安全、条目/展开上限、文件 SHA-256、Schema、计数、
  领域引用和附件元数据，完成后清理临时文件；
- 完整备份密码容器版本 1 使用同一 PBKDF2-HMAC-SHA256 与 AES-256-GCM 安全边界，
  但采用独立二进制协议和 `.nfbak` 扩展名；ZIP 直接流式进入加密流，不在内存中整包编码；
- 密码预览先把经 GCM 认证的 ZIP 解密到私有临时区，再执行原有严格 ZIP 校验；无密码、
  错误密码、密文篡改和越界 KDF 参数均在解析业务数据前安全拒绝；
- 严格校验后逐个来源命例对照当前活动库与回收站，合并同一本地命例的稳定 ID 已存在、
  出生输入相同和四柱相同原因，并携带本地 revision 供后续过期复查；
- 预览 UI 显示来源 App、格式/Schema、加密状态、数据计数和冲突摘要；冲突只读且不默认
  选择任何恢复决策，过多冲突只在摘要中截断展示，不会截断服务层完整结果；
- `BackupRestorePlan` 要求决策与来源命例一一对应且不得重复；没有冲突只允许按原稳定 ID
  导入或跳过，有冲突时直接导入明确拒绝；
- 跳过、按原 ID 导入和保留两份不得夹带合并目标或范围；保留两份必须确有冲突；范围合并
  目标必须来自当前候选、不能位于回收站，且至少选择一个模块或来源字段；
- 生成计划前重新以同一来源出生输入/四柱读取当前库；候选、revision 或回收站状态变化
  返回 `PREVIEW_STALE`，不生成计划；计划保留原 manifest 文件哈希供后续提交复核；
- `RoomDataSnapshot.toDomainCases()` 按既有 sortOrder、分组/标签关联重建完整 `BaziCase`；
  预览逐例保存来源身份、资料、快照、记录/历史、事件/历史、附件、字段证据和组织信息；
- 来源聚合构造会执行 `BaziCase` 的领域引用约束，缺失附件引用、重复子项 ID 等事实不能
  只靠摘要绕过；恢复计划 equality 同时绑定完整来源事实与 manifest 文件哈希；
- `prepareCaseMerge` 在分析前重新核对完整冲突预览，拒绝过期、非候选和回收站目标；
- 合并分析直接调用单命例现有的内容去重与字段差异实现，输出可追加快照、记录/历史、
  事件/历史、组织数量以及别名、姓名、出生资料、五类资料、收藏和置顶前后值；
- 完整备份预览为每个来源命例显示当前选择；无冲突可按原 ID 导入或跳过，有冲突可跳过、
  保留两份或选择具体活动候选进入范围合并；
- 范围合并 UI 显示目标 revision、可追加模块计数和逐字段本地/来源值；空范围时确认按钮
  保持禁用，返回批量预览不会丢失其他逐例决策；
- 全部来源都有显式决策后才能“检查恢复方案”；检查只调用 `prepareRestorePlan`，通过后
  明确显示“尚未写入数据”，修改任一决策会使旧计划失效；
- 计划就绪后仍需第二次明确确认；密码备份在提交时再次输入密码，密码不会持久化或复用；
- 执行器重新打开系统文件并复用密码认证、ZIP 路径/大小/哈希/Schema/引用校验及领域重建；
- manifest、文件数量或完整来源聚合与预览不一致时返回
  `SOURCE_CHANGED_AFTER_PREVIEW`，数据库与附件保持零写入；
- 按原 ID 导入保留来源身份，保留两份生成新命例 ID、revision 1 和来源 ID；记录、历史、
  事件、快照、附件、字段证据、分组和标签全部重建 ID 与引用；
- 范围合并提交复用单命例同一构造器，并在 Room 事务内再次检查目标 revision；重复目标、
  不属于当前差异的字段、没有可追加事实的模块均拒绝；
- 包含附件引用的模块合并当前返回 `ATTACHMENT_MERGE_SCOPE_UNSUPPORTED`，不静默忽略；
- 导入附件先进入 `.restore-staging/<transactionId>`，校验大小与 SHA-256 后原子切换到
  `restored/<transactionId>`，从不覆盖既有附件路径；
- 所有数据库操作处于同一 Room 事务；异常或取消只清理本事务新附件，保留现有事实；
- 文件移动前后使用原子恢复日志记录预期命例载荷；App 启动及下次执行前扫描日志，无 DB
  事实时回收孤儿目录，完整事实及附件一致时安全收尾，不一致则保留现场并要求人工检查；
- Android UI 已开放最终确认按钮，成功后清理旧预览/计划并显示导入、保留、合并、跳过
  和附件数量摘要；
- 错误弹窗保留协议错误代码，导出成功明确图片仅保留引用；
- 启用 App `BuildConfig.VERSION_NAME`，导出文件记录真实当前版本；

## 所有者与边界

- 唯一计算入口：`BaziEngine.calculate()`。
- 唯一增量写入口：`CaseRepository`。
- 唯一完整恢复入口：`CaseBackupService`。
- 唯一单命例交换入口：`SingleCaseExchangeService`；只有第二阶段提交允许调用保存。
- 命例生命周期编排：`CaseLifecycleUseCase`，最终仍通过 `CaseRepository.save()`。
- 重复候选事实：`CaseRepository.findDuplicateCandidates()`。
- 页面不直接访问 DAO，不自行删除、复制或判断重复。
- 页面不生成历史快照；`TextRecordUseCase`、`CaseEventUseCase` 通过聚合写入口统一追加。
- 永久物理清理必须先补齐备份、附件引用计数、失败恢复和明确确认边界。

## 当前限制与风险

- 软删除没有永久清理入口，这是数据安全选择，不是静默遗漏；
- 副本有意不复制记录和附件，完成反馈已明确范围；
- 编辑器仍只支持公历民用时；农历、地区、时区确认和真太阳时未接通；
- `REFERENCES_ONLY` 不携带附件二进制，当前带附件引用命例会拒绝提交；
- 逐字段采用当前覆盖命例标量资料；附件、字段证据和采用盘切换仍需专门事务语义；
- 当前逐例编辑器仍位于长弹窗，尚未重构为适合大量案例的全屏/惰性列表工作台；
- 完整恢复执行器目前集中在 `CaseBackupService`，后续需在保持同一入口的前提下拆分内部
  验证、映射和文件事务组件，避免单文件继续膨胀；
- 带附件引用的模块/字段合并尚无安全选择语义，当前明确拒绝；按原 ID 和保留两份已支持
  真实附件二进制；
- 没有真实进程强杀、OPPO Find N5、系统文件含附件提交或真实问真样本证据。
