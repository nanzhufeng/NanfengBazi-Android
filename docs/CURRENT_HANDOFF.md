# 当前交接：Stage 1 案例数据底座

更新日期：2026-07-30

## 当前任务

- 目标：在进入问真截图迁移前，建立可追溯、可迁移、可恢复的命例数据真值。
- 已修改范围：领域案例模型、Room Schema、仓储、ZIP 备份、空库恢复和脱敏测试。
- 未修改且受保护：正式 UI、OCR、真实问真截图、真实案例、非空库覆盖和真机数据。

## 已实现

- `BaziCase` 聚合覆盖身份、出生输入、个人资料、计算快照、反馈、点评、事件、附件、
  字段证据、分组和标签；
- `ABSENT`、`PRESENT`、`CLEARED` 明确区分来源缺失、已有值和用户清空；
- `CaseRepository` 是命例增量写入唯一入口；
- 修订号阻止旧编辑覆盖新数据，重复稳定 ID 不静默覆盖；
- Room Schema v2 和已提交 Schema 文件；
- v1→v2 迁移保留旧值，并补充来源类型和子项顺序；
- 记录、事件、快照、附件和证据使用显式 `sortOrder` 保留来源顺序；
- 备份格式 v1，包含 manifest、命例、记录、事件、快照、分组、标签、导入证据和附件；
- 导出前核对附件大小与 SHA-256；
- 恢复校验路径、条目数、展开大小、文件集合、SHA-256、数量和引用完整性；
- 当前只允许恢复到空库和空附件目录；
- 附件提交失败会清除本次数据库写入；
- 密码保护未实现时返回结构化拒绝，不生成明文冒充加密文件。

## 当前限制与风险

- `app` 尚未依赖或组装 `core:data`，没有可操作的新建、列表、备份或恢复页面；
- 恢复只支持空库，不支持跳过、保留两份、模块合并或逐字段选择；
- 没有密码加密；
- 没有进程被系统强杀时的跨数据库/附件恢复日志；
- Room 2.8.4 与当前 Kotlin 2.0.20/KSP Schema 导出存在 ABI 冲突，本阶段保留 2.6.1；
- 尚未使用 Android 系统文件选择器和真实 ZIP 做设备级验收；
- 尚未导入任何真实问真截图。
