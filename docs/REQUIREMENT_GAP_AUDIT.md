## 状态定义

| 状态 | 含义 |
|---|---|
| 已完成 | 生产实现与当前自动证据均存在 |
| 部分完成 | 已有真实子链路，但仍缺产品要求中的字段、入口或更高等级证据 |
| 未开始 | 只有文档或预留模型，没有生产入口 |
| 待外部验收 | 代码可继续推进，但最终结论需要设备、隐私批准样本或用户确认 |

## 11. 当前最优下一阶段判断

选择 **Stage 4A：出生输入与算法结果完整化**。

依据：

1. Stage 3A 已把记录、分析、事件、分类、历史与命例生命周期的用户语义固定下来，
   “按模块导入”和冲突预览已有明确对象。
2. Stage 3B 已补齐 JSON、附件包、完整备份、非空冲突计划、失败回滚与进程中断恢复，
   可以在不放大数据安全债务的前提下扩展出生输入和计算结果。
3. Stage 4A 可先用公开与合成边界完成，不需要真实问真资料、账号或真机授权。
4. 问真输出仍是迁移保真首要验收标准，但算法真值必须来自版本化规则与边界测试，两者
   不得互相替代。

Stage 3A 已完成五个受控增量：

- 编辑命例别名、姓名和出生资料后重新计算并以期望修订号保存；
- 普通笔记、命主反馈、师傅点评和分析记录的新增、修改、删除；
- 关键事件的新增、修改、删除；
- 分组、标签、收藏、置顶、最近查看、四柱搜索、组合筛选和多种排序；
- 可恢复软删除、回收站、恢复、命例复制和重复候选提示；
- 文本记录、反馈、点评、分析和关键事件的新增/修改/删除版本历史；
- 综合、性格、事业、财运、感情、健康、学业、家庭、其他统一分析分类；
- 关键事件支持可选标题、综合/学业/事业/财运/感情/家庭/健康/其他八类结构化类别，
  当前值和全部历史均可读取；
- Room Schema v6 与兼容迁移，备份格式 v1 向后兼容历史数组和空候选默认值；
- 永久物理清理当前有意不开放，避免绕过附件与备份恢复边界；
- 每种失败均保留用户输入并给出中文原因；
- 自动测试、完整构建、Lint、模拟器冒烟、文档和独立本地提交。
