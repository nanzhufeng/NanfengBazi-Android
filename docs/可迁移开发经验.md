# 可迁移开发经验

> 2026-10-11复核，依据当前e48996b源码/配置/测试与可达Git；项目事实见[完整开发档案](南枫八字完整开发档案.md)，覆盖与历史清单见[复盘证据](verification/project-retrospective-20261011.json)。经验是方法，不是目标平台验收结果。

## 一、通用原则

| 触发条件 | 可迁移方法 | 本项目依据 | 验证与限制 |
| --- | --- | --- | --- |
| 一个页面包含父对象与多个子状态 | 为聚合明确唯一所有者，以稳定ID + revision原子发布；缓存缺失作为未知 | StageTwoViewModel、RoomCaseRepository、D-162/167 | 切对象/返回/并发回读测试；目标产品重新定义聚合边界 |
| 首屏被维护或慢写盘阻塞 | 恢复投影先呈现，真值静默校准；发布锁和持久化锁分开、旧写代次守卫 | CaseCatalogStore、CaseCatalogStoreTest | 挂起写入/维护的行为测试和冷入口；缓存不变为业务真值 |
| 多入口计算口径分裂 | 领域层输出版本化事实，页面/导入/反查复用同一合同 | BaziEngine、ProfessionalFortuneResolver、TymeFourPillarsLookup | 正向/反向和选择回定位一致性；不复制本项目算法 |
| 外部资料与本机结果冲突 | 来源、计算、采用分别建模；保存来源与采纳证据 | WenzhenSourceFidelityContract、CalculationArchiveComparison | 冲突/缺失样本；OCR一致不证明领域正确 |
| 导入/恢复可能破坏既有库 | 零写入预演、显式决策、提交再认证revision/文件、事务+journal | CaseBackupService、RestoreJournalProtocol、CaseBackupServiceTest | 篡改/过期计划/附件失败/中断恢复；不能照搬实体或策略 |
| 大库编码造成内存峰值 | 稳定顺序、流式JSON、清单哈希及IO；分阶段处理 | CaseBackupService、D-163 | 实际数量/峰值与往返完整性；流式编码不是零内存聚合 |
| 用户离开却显示网络失败 | 取消独立于失败，保持控制流，防止旧任务覆盖新选择 | cloud-sync-contract、BaziCloudCore及取消测试 | 主动取消/Worker停止；业务失败仍须结构化解释 |
| 密集页面滑动/切换卡顿 | 按视口渲染，状态按对象身份保存，避免每个标签清空重算 | StageTwoScreens/ViewModel、交互合同、性能审计 | 连续点击/标签/宽窄返回；不能仅凭Lazy API宣称性能通过 |
| 导出与页面显示不一致 | 临时展开同一真实渲染器，finally恢复现场 | CaseDetailLongImageCapture、D-154 | 成功/失败/取消及返回；平台图像/文件交付另实现 |
| 视觉表面与点击反馈外溢 | 表面/clip/click/pressed/ripple/focus共用形状，保留命中尺寸 | InteractionShapeContractTest、共享主题 | 目标平台真实交互；源码匹配测试不是视觉证明 |
| 声称优化已生效却只有配置文件 | 确认平台安装/编译状态，声明冷/热与宿主负载，拆分不同指标 | baseline-prof.txt、性能采样脚本及审计 | 启动/帧/点击/工具空闲分别测量，不拼成零延迟承诺 |
| 外部能力与本地真值混淆 | 定义启用/发送/采用边界和后台授权生命周期，结果可追溯 | AI设置/点评、BaziCloudSyncCoordinator、云合同 | 本地模拟不替代真实身份/网络/服务验证 |
| 新规范阻断已有产品正常更新 | 先确认现装身份，定位匹配原密钥、受控接入和验签，避免换签绕过 | app/build.gradle.kts、既有覆盖报告 | 同签名与数据保持；历史身份例外不成为新项目默认 |
| 同源码多次构建却产物漂移 | 区分源码、依赖/配置与动态元数据，冻结最终包再验签/回读 | APP_BUILD_TIME、checkpoint报告 | 实际产物哈希和源码范围；不把新构建称为同一个包 |
| 文档反复把旧状态当现状 | 长期规则、设计决策、当前状态、历史证据分层；按代码记录冲突 | 根AGENTS、PROJECT_STATUS、复盘冲突表 | 基线/时间/链接检查；文档完成不刷新旧测试时间 |

这些原则可迁移到桌面/Web/iOS等，必须在目标技术栈重新建立所有者、存储、生命周期和证据。仓储事务可由其他数据库实现，Compose视口状态可由目标UI框架实现；不要求原类名或目录结构。

## 二、该项目专属内容

| 内容 | 项目依据 | 专属前提 |
| --- | --- | --- |
| 精确立春换年、十二节换月、默认23点换日及显式晚子同日 | CalculationProfile、TymeProfessionalFortuneResolver、domain-rules | 八字领域规则和用户选择，不能成为所有日期应用的默认日界 |
| 真太阳时民用年/月、真太阳日/时PROVISIONAL | CalculationProfile、SpaTrueSolarTimeCalculator、TymeBaziEngine | 外部边界对账仍缺失，不能当统一历法标准 |
| 命例ABSENT/PRESENT/CLEARED、计算快照、笔记/事件历史 | CaseModels、CaseRepository、DATA_CONTRACT | 特定资料保真与revision协议 |
| 问真九列证据、四柱反查、资料候选确认 | WenzhenP0Parser/专业解析器、ScreenshotImportCommitter | 来源布局、字段和命理一致性门禁 |
| 名人资料/用户资料库区分及来源可信度 | UnifiedCelebrityCatalogImport、Room迁移9→11 | 产品资料分类；素材/原文不自动进入其他项目 |
| 合盘、格局、旺衰、盲派、称骨、神煞 | core/domain相关分析器及测试 | 规则、样本、文化解释与用户语言边界 |
| 云以非空本机为源、空白设备解锁恢复 | decideBaziCloudSyncAction、cloud-sync-contract | 本项目加密备份产品模型，不等于多端协作合并模型 |
| 80%记录四柱预览及十列专业视口 | StageTwoScreens、交互合同、当前性能/视觉报告 | 已确认信息密度与截图反馈，不是跨项目固定数值 |

## 三、不可直接照搬的部分

| 项目资产 | 不能照搬的原因 | 可保留的方法 |
| --- | --- | --- |
| 包名、版本、证书、APK哈希、设备号和绝对路径 | 都是具体产品/时间点身份 | 在目标项目重新核验，保留正常保数据升级门禁 |
| Android ProfileInstaller、WorkManager、Keystore/Manifest | 平台生命周期、编译和权限机制不同 | 定义等价优化生效证据、后台调度及密钥保护 |
| Room Schema12、备份ZIP字段、restore journal格式 | 实体、关系、版本、附件和恢复策略专属 | 防御性解析、事务、显式计划、可恢复提交 |
| Google/Supabase配置、共享恢复码与AAD | OAuth/账号/RLS/RPC/App身份不同 | 重建目标配置和隔离合同，禁止复制凭据/真实密文 |
| AI预设/成本估算/视觉OCR生产默认 | 模型能力、接口、价格及用户许可会变化 | 发送范围、采用记录、失败/取消和真实调用验证；目标项目重新核对 |
| 固定像素、皮肤素材、折叠屏布局、命理文案 | 产品密度、品牌和目标屏幕不同 | 同形反馈、语义令牌、稳定锚点与真实视觉验收 |
| 历史脚本或旧Debug安装结果 | 设备策略变化，脚本存在不等于当前授权 | 按当前隔离规则执行；本用户所有项目禁止connected任务 |
| 1020测试数、旧截图、旧安装/服务结论 | 范围含变体重复、具体版本与环境 | 只迁移证据分层方法，目标项目重新跑相关门禁 |
