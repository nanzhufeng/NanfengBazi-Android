# 可迁移开发经验

> 只收录可由当前代码、项目文档或 Git 记录支撑的经验。项目专属前提不自动推广为通用规则。

## 通用原则

| 原则 | 可迁移做法 | 依据 |
|---|---|---|
| 数据所有权先于缓存体验 | 多子状态页面以对象 ID 与 revision 共同绑定；缓存未命中不能证明数据库为空 | `architecture-governance.md`、`StageTwoViewModel.kt` |
| 大数据先限内存再谈同步 | 整库导出使用稳定顺序、流式写入、哈希和 IO；不构造整表 JSON 字符串 | `CaseBackupService.kt`、`app-experience-audit.md` |
| 取消不是失败 | 页面离开、更新和 Worker 停止保留为取消控制流，不显示成网络错误 | `cloud-sync-contract.md`、云同步实现 |
| 预览与写入分离 | 导入/恢复先做零写入预演，确认且校验仍有效时才提交 | `DATA_CONTRACT.md`、`CaseBackupService.kt` |
| 验证按证据层报告 | 静态、测试、构建、设备和真实服务不能相互替代 | `TEST_STRATEGY.md` |
| UI 重排不复制业务链路 | 表面层可调整，但复用既有 ViewModel/用例/仓储；形状、点击与反馈同源 | `TEST_STRATEGY.md`、`InteractionShapeContractTest.kt` |
| 直接定位不借用近似动画 | 语义是“跳到指定项”时直接使用该项的列表状态；不要复用带预滚动或分组补偿的相似跳转，否则会产生可见回跳 | `StageTwoScreens.kt`、`InteractionShapeContractTest.kt` |
| 外部能力须有真值边界 | AI/云端结果保留来源与确认，不覆盖本地计算或用户原始资料 | `cloud-sync-contract.md`、`AiCommentaryFeature.kt` |

## 该项目专属内容

- 八字排盘唯一入口是 `BaziEngine.calculate()`；Tyme4j、真太阳时、节气、子时和起运口径需连同黄金样本维护。
- 命例聚合的 `ABSENT/PRESENT/CLEARED` 三态、revision 冲突和记录/事件历史协议来自本项目数据合同。
- 完整备份 ZIP 与云端加密结构化快照范围不同；云端明确排除附件、来源图片、字段证据和模型密钥。
- 专业截图/OCR 的九列门禁、反查与“来源值/计算值/采用值”三分法，针对问真式资料导入。
- 合盘输出必须把领域信号、个案信息和面向普通人的建议分层，并遵守文化娱乐与敏感信息边界。

## 不可直接照搬的部分

| 内容 | 原因 | 正确迁移方式 |
|---|---|---|
| OPPO 覆盖安装流程 | 包名、签名、数据和设备策略均是实例化事实 | 迁移“同签名、前置核验、不卸载”原则，重定义目标设备门禁 |
| v1 备份格式与 Room schema | 实体、附件、冲突模型和历史版本属于本项目 | 迁移防御性解析/显式计划，重新设计自身契约与迁移测试 |
| Google/Supabase 云协议 | AAD、恢复码、账号隔离和 OAuth 客户端依赖产品身份 | 迁移端到端加密和授权分层，不能复用配置或账号语义 |
| 固定 APK 版本、哈希、提交号 | 是时间点证据，可能已失效 | 每次从当前分支、构建产物和签名重新核验 |
| 命理与合盘文案 | 依赖领域规则、样本和产品的文化娱乐定位 | 先建立目标领域的可审计规则与用户语言边界 |

## 可复用流程

1. 先盘点当前工作树、配置、测试与 Git，再写结论；历史交接只作线索。
2. 按“领域 → 数据 → 用例/ViewModel → UI”确定改动边界，避免页面层重复计算或直写数据库。
3. 先补最小失败回归，再跑与改动相称的 JVM/静态/构建门禁。
4. 真机、真实账号、外部服务、覆盖安装与数据恢复单独授权、单独执行、单独报告。
5. 文档同时写清确认事实、未验收项和代码/文档冲突，避免把旧交接当作当前状态。
