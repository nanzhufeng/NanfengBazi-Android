# 决策记录

## D-201 格局只按八正格取用，月令比劫不直接成格

- 状态：已接受
- 决策：`BaziStructuralProfileAnalyzer` 升为 `structural-profile-v3`。取格固定先看月令主气、中气，再以年／月／时透出的同一藏干优先；余气不参与取格。主气、中气都没有透干时，只以主气定格。只允许正官、七杀、正财、偏财、正印、偏印、食神、伤官进入格局。比肩、劫财只保留为旺衰依据，严禁再输出“建禄格”或“月劫格”。月令比劫而无八正格透干时显示“未取格”，不伪造格局。旧快照按规则版本只读重算，不写回命例。
- 依据：月令司令与天干引助是取格的共同前提；《子平真诠》论建禄月劫明确禄劫不能直接取为用，应另审全局透干。GitHub 的八正格实现也将比劫与八正格分离。UI 只显示“旺衰／格局”，不再加“候选”。

- 边界：做功路径是可核验的命局结构，不等同于合化已成、墓用已开、岁运已引动或现实吉凶结论。

  天干、补根或页面计算混入分母；表层个数、含藏数量仍保持独立事实统计。
- 依据：用户确认的图示明确给出月支 50%、时支 35%、日支 10%，剩余年支 5%；第二张图明确给出同党占比的
  七档旺衰区间。图示漏标 50–60，系统将该连续区间归入“平衡”。
  [GitHub `bazi-skill`](https://github.com/jinchenma94/bazi-skill/blob/main/references/wuxing-tables.md)复核藏干本中余的
  60／30／10 分层，[GitHub `bazi-report`](https://github.com/Cyberseer-976/bazi-report/blob/main/scripts/calculate_bazi.py)
  复核同党（印枭＋比劫）与异党（食伤＋财＋官杀）的归类。该比例是明确版本化的民间旺衰辅助口径，不冒称所有流派的
  唯一标准；盲派宾主、体用和做功仍由 `MangPaiProfile` 独立输出。

## D-198 基本信息参考模块标题居中，阴阳按原局八字具体统计

## D-197 AI 调用记录只展示可复核的本地估算金额

- 背景：八字 AI 调用记录需要补充金额，但当前兼容接口只稳定返回模型与输入／输出 Token，未提供可作为结算凭证的统一账单金额。
- 决策：调用成功后，仅在输入与输出 Token 完整、模型具有版本化公开价目时按请求时间生成本地估算快照；UI 始终以“估算”标识。历史记录没有快照时，按原请求时间重新推导。自动路由、未知模型、Token 缺失或异常值均显示“暂不可估算”。
- 后果：记录可显示人民币折算金额且不把本地估算伪装成供应商实扣；实际提供商账单若未来接入，须独立保存来源与原币金额，不能覆盖本字段。

## D-196 应用内图标随字体档位只做视觉缩放

- 状态：已接受
- 决策：所有 App 内 Material 与资源图标统一通过主题级 `Icon` 包装器读取 `LocalAppIconScale`；小号／标准／大号分别缩放为 `0.80`／`1.00`／`1.12`。图形以绘制变换缩放，既有 dp 布局、卡片间距、IconButton 尺寸与触控范围不变；系统通知和桌面启动图标不受该偏好影响。
- 原因：字体大小改变而图标保持基线，会使小号界面显得图标过重、大号界面显得图标偏小；同时放大布局或点击区会破坏既有排版与交互几何。

## D-195 设置中的应用内字体大小采用三档本地偏好

- 状态：已接受
- 决策：设置页在“皮肤”下方新增“显示 → 字体大小”，提供“小号／标准／大号”三项并在点选后立即生效；“标准”固定表示用户开启本功能前的现有字号，小号相对标准减 `2sp`、大号加 `1sp`，最小显式字号保持 `8sp`。偏好只存于本机显示设置，不改写命例、排盘快照或系统无障碍字体比例。
- 原因：字号不应由某一页面单独控制，否则用户在设置里选择后会在密集命盘、日历或列表中得到不一致的阅读体验。根主题与所有显式字号共用同一比例入口，既保证全局一致，也保留系统字体缩放作为独立的无障碍能力。

## D-194 合盘记录管理统一为底部图文操作栏

- 状态：已接受
- 决策：八字合盘、合盘结果、合盘记录列表和记录详情的顶栏一律使用返回图标；合盘记录默认顶栏另保留无文字的管理图标。点管理后，顶栏不再挤入全选、删除和完成。管理态仅在底部显示同一组等宽的“图标＋文字”操作：全选／取消全选、删除已选数量、完成。删除确认和读取失败后的重试继续使用文字，避免高风险动作或恢复路径仅靠图标猜测。
- 原因：顶部同时承载三项管理动作会挤压标题和导航，而底部单独重复一个删除按钮又浪费空间并造成同一操作出现两次。将低风险的批量管理收敛在底部，既保留直接可读的文字，也能减少顶部汉字和重复入口。

## D-187 合盘记录以冻结快照优先呈现，历史补齐不阻塞入口

- 状态：已接受
- 决策：首次进入八字合盘时，合盘历史只读取本机冻结报告快照后即标记为已就绪；无记录也属于已就绪状态。历史记录页必须直接呈现该快照，不能等待双方命例查询、旧报告补齐或回写完成。补齐仅在后台执行，失败保留已读快照，不以全屏加载或空态覆盖。相同 `StageTwoViewModel` 会话内再次进入合盘时复用已读历史，不得再次调用历史 `list()` 或重置为加载态；用户显式“重新读取”才允许重新加载。
- 原因：冻结报告本身已具备打开列表和报告详情所需资料。把可选的历史兼容补齐串在入口读取上，会让用户每次看到“正在读取合盘记录”，并把本机已保存资料的正常页面延迟到后台维护完成之后。

## D-187 旺衰比例与盲派断事框架分层冻结

- 状态：已接受
- 决策：`WangShuaiProfileAnalyzer` 以 `month-command-hour-root-v1` 单独保存旺衰比例：年、月、时干为 0.5／1.5／1，年、月、日、时支为 0.5／3／1.5／1，藏干按本／中／余气 0.7／0.3／0.15 分摊；时支只有含日主或印星根气才按层级补 1.5／0.75／0.4。它是南枫明确版本化的工程模型，不称为古籍固定百分比。`BaziElementDistribution` 退回盘面五行统计，不再输出同／异党结论。
- 盲派：`MangPaiProfileAnalyzer` 以 `mangpai-binzhu-zuogong-v2` 冻结日时主、月近宾、年远宾，十神体用归类、跨主宾干支关系做功路径及八字逐字取象；路径不能等同做功已成、合化成立或现实断语。页面固定将盲派卡置于称骨算命上方。
- 原因：旺衰比例需要可复算的月令与通根权重，而盲派宾主做功服务于断事取象；混用会把两个流派的不同问题误作同一结论链。

## D-186 合盘选人页复用记录行几何，合盘顶栏标题按完整宽度居中

## D-185 旺衰与格局使用本机证据化候选，问真来源保持独立

- 状态：已接受
- 决策：`BaziStructuralProfileAnalyzer` 是旺衰与格局候选的唯一规则入口，并由 `BaziEngine.calculate()` 在同一份 `CalculationResult` 中冻结 `structuralProfile`。它必须先取月令，再列月令藏干／透干、日主通根与天干生扶克泄耗的可审计证据和置信度；常规格局只作候选。从弱、专旺、合化、三合和三会只作为复核项，禁止直接定格，且不输出喜忌、用神、吉凶或现实关系结论。
- 兼容：历史快照与旧合盘报告缺少该字段时，只能按其各自冻结的四柱补齐候选，不重新排盘、不读取新命例状态、不回写个人命例。`chart.user_strength` 和 `chart.user_structure` 继续是问真来源记录，可用于对照，但不得覆盖算法候选。
- 原因：来源字段为空时合盘把格局显示为“未记录”，而把八个表层字符计数直接冒充旺衰又不可靠。月令、藏干、透干、通根和生扶克泄耗的证据链既能避免空占位，也能保留传统命理存在流派差异时的可复核边界。

## D-184 合盘关系必须先表达生克方向，再叠加合冲刑害；十神颜色跟随对应天干

- 状态：已接受
- 决策：合盘的夫妻宫、年支和夫妻宫 ↔ 对方年支对比，必须以双方实际地支的主五行先给出同五行、左生右、右生左、左克右或右克左。六合、三合、冲、害、破、刑是第二层的结构证据，不得因其未命中而写“未见直接作用”。面向用户时，相生说明为资生、支持、较主动投入的方向；相克说明为制约、占据或消耗风险，并说明适度制约可帮助形成规则；同五行说明默契和同质僵持的双面性。日主行使用同一表达原则。
- 配色：合盘十神文字的颜色由其对应天干的统一五行色决定；藏干每一项和大运的天干／十神均使用该规则，大运地支继续使用自身五行色。角色颜色只描述男／女身份，禁止污染命盘事实颜色。
- 边界：这些关系说明只读取双方采用快照中的四柱、日主和大运干支；不重新排盘。大运十神若快照没有独立保存，允许由该大运天干相对已保存日主补齐，因为这是显示所需的唯一缺失投影。
- 原因：合冲刑害不是五行作用的全部；把“未命中合冲刑害”说成“没有关系”会漏掉相生的付出方向与相克的制约方向，也会误导普通用户。

## D-183 合盘基础信息只复用双方采用快照，实岁大运使用精确交运边界

## D-166 名人列表统一展示目录与来源分组分离

- 状态：已接受

- 原因：把“历史名人、国外、名人案例”等导入来源分组与新资料包领域分组同时暴露，会造成重叠、零散分组和计数与列表不一致；直接重写原始 351 条又会破坏问真资料的可追溯性。展示层统一分类可同时保留原始资料与清晰阅读路径。

## D-165 已核同一名人的跨资料包重复项只在列表合并

  列表、详情与归档快照漂移。把确定性字段一次固化在版本化结果中，既能与截图逐项对照，
  又不会把神煞、断语等尚未建立规则真值的内容混入当前完成范围。

## D-042 童限结束时刻统一称为精确交运时间

- 状态：已接受
- 决策：沿用 Tyme4j `ChildLimit` 的版本化结果，把 `endTime` 映射的

- 原因：Tyme 官方明确“童限结束的公历时刻，即开始起运，是大运的开始”，并在排盘示例

  同时避免把出生基准 `startAt` 错标为交运时间。

## D-043 即时排盘与保存共用计算准备链

- 状态：已接受
- 决策：`CreateCaseUseCase.preview()` 与保存入口共用同一私有计算准备链，包括输入校验、

- 原因：独立实现一套“快速排盘”会造成预览与保存结果漂移；先保存再删除又会污染命例库
  与审计历史。共享计算、分离持久化可以同时满足即时查看、零写入和唯一真值入口。

## D-044 时间精度与时间来源必须显式留证

- 状态：已接受
- 决策：`BirthInput` 增加兼容默认值为 `UNKNOWN` 的 `TimeSourceType`，并扩充
  `TimePrecision.APPROXIMATE`。新建、即时排盘和编辑共用显式精度/来源选择与可选说明；

- 原因：秒数为 0 既可能代表“精确到分钟”，也可能只是系统补零，不能由软件反向猜测。

## D-045 出生时间候选是命例内部版本，不复制命例

## D-046 双实现只用于测试差分，生产仍保持唯一引擎

## D-047 图片原件与可恢复会话先于具体 OCR 实现

## D-048 首个 OCR 使用 bundled 中文模型并显式移除联网权限

## D-049 长图分段与重复判断只产生证据，不自动合并

- 状态：已接受
- 决策：超过单次安全像素阈值的截图使用纵向重叠区域解码，禁止先把整张长图展开到内存；
  每段 OCR 边界框加回分段纵坐标，并按相同文字与原图区域重叠去重。每张私有图片同时
  保存宽高与 64 位 dHash；SHA-256 相同标记为完全重复，dHash 汉明距离不超过版本化阈值
  只标记“疑似相似”，二者都不自动合并命例。批次识别保存逐图片失败结果，局部重试只
  处理失败图片并复用已有成功 OCR。
- 原因：问真长截图可能远超安全解码内存，而简单裁切会重复或截断文字；感知哈希只能
  表达视觉近似，不能证明两张图属于同一命例。把坐标、哈希和逐图结果作为可核对证据，
  才能兼顾稳定性、可恢复性与“不串例”底线。

## D-050 后台识别使用唯一 WorkManager 任务，删除必须二次确认

  只读取 Room 会话和私有图片，不持有外部 URI，也不要求网络约束。当前固定

  Kotlin metadata 2.0 的 Lint 工具链兼容；2.11.2 会令现有 Lint 因 metadata 2.1 崩溃，

- 原因：ViewModel 协程不能保证页面离开或进程重建后继续执行，而关闭 Lint 规则来迁就

## D-051 多图归组采用全组一致的强身份信号

## D-052 问真 P0 解析结果必须先进入待核对证据层

## D-053 问真候选只有人工采用且本机复算一致才能写入正式库

- 状态：已接受
- 决策：核对页逐项展示来源值、规范值、计算状态与采用值；字段和完整原文的采用状态

  阻止该候选，不回滚已确认候选。
- 原因：问真列表通常只显示日期和四柱，没有可直接采用的精确钟表时间。按时支选取
  代表时刻只能作为“时辰精度”的可审计输入，不能冒充精确出生时刻；再以来源四柱做

## D-054 OCR 修正只改规范值并强制重新采用

- 状态：已接受
- 决策：问真用户列表中的四柱即使 OCR 无法规范化，也必须保留为带原图文件名、原图
  边界框和原始文字的待核对字段。核对页允许人工修正名称、性别、公历生日与四柱；
  保存时按字段类型严格校验，只更新规范值并标记 `userEdited`，来源原文和边界框保持

- 原因：低置信度 OCR 如果只显示“未识别”而没有可修正证据，会使批量迁移在单个错字处

## D-055 问真导入遇到重复命例必须显式选择保留两份

- 状态：已接受

## D-077 四柱反查只返回经正向引擎复核的民用代表时刻

- 状态：已接受
- 决策：`core:domain` 的 `FourPillarsLookup` 是四柱反查唯一公开入口，首版固定支持
  1900–2100 年、IANA 时区和两种子时口径，只返回民用代表时刻。Tyme4j 1.5.1
  `EightChar#getSolarTimes(int,int)` 生成原始候选后，每个有效时区 offset 都必须经过
  `BaziEngine.calculate()` 复算一致才可展示；DST 跳时排除，重叠时按 offset 分列。
  候选不自动保存为命例，页面明确其不是出生分钟唯一证明且未做真太阳时推算。
- 全局状态例外：字节码确认 `getSolarTimes` 内部调用 `LunarHour.getEightChar()`，
  因而会读取进程级 `LunarHour.provider`。只有 `TymeFourPillarsLookup` 可在进程级锁内
  按本次子时口径临时切换，并在成功、异常或取消后用 `finally` 恢复；既有正向计算继续
  使用实例 provider，不读取或改写该全局状态。
- 原因：库反查结果提供候选生成能力，但不能代替项目版本化规则、时区证据或唯一正向
  真值。限定已验证年份、显式时区/口径、逐候选复算和清晰免责声明，才能让结果可解释、
  可复现且不把时辰候选夸大成出生分钟证明。

## D-182 记录定位和合盘对照必须复用既有状态与冻结快照

- 状态：已接受
- 决策：记录页的“置顶定位”是字母索引之外的直接定位动作：仅在用户点按时选择首个置顶案例的列表索引，直接滚动到该项；不得借用按字母跳转的预滚动／动画，从而避免先显示 A 再回跳。其默认视觉与字母索引同级，只有按压或选中才出现共同的圆形状态。
- 合盘结果只保留一次家庭关系对照：双方年支后直接展示双方夫妻宫及交叉项。核心关系、家庭互动、命盘结构和关系分组共享同一列宽、竖线与“对比项／双方实际姓名／解析”表头；分组用“相处优势／相处提醒”表达。所有展示来自已冻结的双方采用快照与既有关系信号，不重排、不回写命例。
- 入口与输入：首页合盘、万年历采用同一胶囊任务卡；专业细盘观察时刻可复用出生时间快速定位解析，但只更新弹层草稿，仍以一次确认提交。设置不得为首页已有合盘入口另建可点击的重复入口。
- 原因：把定位、表格几何、姓名与解释语义收敛到现有单一列表状态和冻结报告，既消除跳动与重复内容，也避免新增第二套关系计算、日期提交或功能入口。
