## 已确认根因与修复

1. **固定案例主引擎原已正确**：北京时间2000-02-04 08:00为己卯／丁丑／兔。不能宣称该主引擎案例修复前失败；截图中的已采用旧盘是否由旧版、来源采用或其他输入造成，未读取用户数据库，仍UNKNOWN。
2. **万年历同页不一致**：`TymeAlmanacReader.toDetails` 的年／月／日摘要读 `sixtyCycleDay`，四柱明细却读所选时辰 `EightChar`。摘要在立春整日切换，早于真实交节。现在摘要与明细同源，日历网格、农历年、宜忌仍保留其日历语义。
3. **出生时区证据未参与年／月比较**：`TymeBaziEngine`虽归一化并保存历史offset，旧八字适配仍把出生墙上读数直接与北京时间节气比较。现在先还原出生Instant，再比较同一提供者的立春／十二节Instant；同一真实时刻跨时区、不同经度或设备时区不改变年／月。日／时柱策略不改。
4. **未知秒被当00秒**：旧分钟、小时、时辰输入仍产生单一确定盘。现在用半开可能区间，跨节返回结构化年／月／生肖候选；预览／保存显示待确认并零写入，不能强制采用。APPROXIMATE没有误差半径时保守覆盖所知民用日期；UNKNOWN继续拒绝唯一命盘。
5. **万年历丢弃分秒和23点**：时间选择原只传hour，随后按时辰代表点重建，23点会被折回当天00点。现在保持实际时分秒及精度，原选择器增加可选秒（含未知）；所选时辰表示范围。跳转、今天、日期／月份切换、缓存键、带入排盘共享同一查询。带入明确使用固定UTC+08的IANA标识Etc/GMT-8，避免历史上海地方平时／夏令时再次改变时刻；普通出生录入仍保留真实出生地历史时区。默认观察时钟显式使用北京时间，不跟随设备当前地区。刷新旧画面期间禁止采用过时选择。
6. **反查漏边界候选**：旧Tyme反查默认北京时间；民用扫描只在原生空结果时使用，并以正午年／月筛掉整日。现在补本地民用日和真实交节的候选，结果逐项由BaziEngine复算。按60日推进与干支年预筛，节气年缓存有界，不做全日逐分钟穷举。
7. **截图提交错误假定单快照**：反查允许多个合法候选，重复检查却用 `.single()`。回归已捕获“重复命例检查失败”；改用唯一明确采用的快照，保留其余候选。
8. **资料库升级不能静默替换旧盘**：约略时间跨节的资料保留来源、出生事实与原文，不生成伪确定采用盘，不自动采用另一备选。统一资料库574条仍可完整预检同步；跨规则版本的自动维护保留已有出生输入、全部候选与旧采用／历史快照。显式编辑重排仍经原用例生成新快照。

## 唯一计算与时标链路

```
出生公历／农历 -> 原公历墙上时间 -> BirthTimeZoneResolver(历史ZoneId、offset、DST消歧)
 -> 出生Instant + 原输入精度
 -> TymeSolarYearMonthResolver(立春、十二节固定北京时间一次转UTC)
 -> 确定年／月或明确双候选
 -> TymeBaziEngine最终四柱 -> 年支生肖、明细、派生分析、快照／AI／导出
```

万年历、专业观察与反查复用该年／月入口；专业观察轴为北京时间，v2交运／大运起止采用同坐标。原始出生日期、出生地时区、日／时柱与真太阳时输入独立保存。PROVISIONAL枚举标识兼容保留，v2年／月语义由现行[领域规则](domain-rules.md)规定。

区间为 `[L(Y), L(Y+1))`；等于正式提供者的交节秒算新年。正式提供者锁定Tyme4j 1.5.1的 `SolarTerm.julianDay.solarTime` 秒级输出；实际JAR反编译确认 `qiAccurate` 含+1/3天，因此按UTC+08解析一次，不能直接当UTC JD，也不能重复加8小时。不把页面分钟标记或假设某年2月4日零点当边界；不宣称库输出的小数或独立求解器毫秒代表天文毫秒准确度。
