# Android 启动图标保真构建规范

## 1. 适用范围与唯一事实源

- 当前唯一母版是 `design/assets/app-icon-master.jpg`。它只读保存，不能以旧导出位图反向替代，也不能用生成式工具重绘。
- 本规范只规定 Android 图标包装，不改变母版的图案、色相、比例关系或阴影语言。
- `mipmap-*` 兼容资源必须把本规范的材质背景与实际比例前景扁平化导出；不能直接缩放带白画布的母版。Android 26+ 使用同一视觉的两层自适应资源。

## 2. 目标视觉

启动器中应当看见一张完整、留有呼吸空间的米色图标：米色材质从图案内部自然延展到系统蒙版边缘；“太”、四柱、金点、枫叶完整可见。禁止出现白边、白色外框、独立圆角卡片、单色补底、被裁断的图案或被放大的满画布前景。

## 3. 分层构成

| 层 | 工程资源 | 必须满足 | 禁止做法 |
|---|---|---|---|
| 材质背景 | `drawable-nodpi/app_icon_background.png` | 1254×1254、全不透明；只从母版中不含图案的米色区域提取色调与明暗走势，生成连续材质场并延展至全画布 | 复用原图的白画布；填充固定单色；保留原米色圆角卡片边界；把完整图案烙进背景 |
| 图案前景 | `drawable-nodpi/app_icon_source.png` | 1254×1254、透明底；只含原图的图案与必要的原始软阴影，图案在最终画布中缩放定位 | 把米色卡片、白画布或整张母版放进前景；以矢量/AI 重画图案；在构建后另行缩放前景 |

`mipmap-anydpi-v26/ic_launcher.xml` 与 `ic_launcher_round.xml` 必须继续只组合这两个层：背景指向 `app_icon_background`，前景指向 `app_icon_source`。

## 4. 当前母版的比例基线

- 当前 OPPO Find N5 / ColorOS 基线：`app_icon_source.png` 内的图案缩放为母版画布的 **57%**，居中。
- 57% 是实际写入前景 PNG 的比例，绝不是只用于本地预览的额外缩放。预览、APK 与真机必须引用同一份前景资源，不能发生“预览缩小、APK 未缩小”的第二套比例。
- 后续若用户要求调整，只允许在真实启动器截图对照后以小步（通常不超过 3 个百分点）修改该实际前景比例；背景层不随之缩放。

## 5. 固定构建顺序

1. 校验母版路径、尺寸与哈希；不修改母版。
2. 从母版的非图案米色有效区域构建全画布连续材质背景，消除母版外侧白画布与原圆角卡片边缘。
3. 提取原图图案、金色细节和必要软阴影为透明前景；背景色像素不得随前景带入。
4. 在 **前景 PNG 本身** 应用经真机反推的比例（当前 57%），居中导出；再与背景按 1:1 合成做本地检查。
5. 用同一份背景与实际比例前景导出 `mipmap-*` 兼容位图，并替换 Android 资源后构建 APK；不得把临时合成预览当成最终资源。
6. 真实启动器覆盖安装后，重新读取桌面图标；只在用户视觉确认后更新交接、决策状态和提交。

## 6. 不可省略的校验

### 文件层

- 背景与前景均为 1254×1254 PNG；背景 alpha 必须全为 255，前景必须存在透明区。
- 自适应 XML、Manifest 的 `icon` 与 `roundIcon` 路径保持完整；legacy 位图与 adaptive 合成图不得出现白画布；不新增网络权限或外部调用。
- 本地 1:1 合成图中，画布边缘不存在白色像素带或可辨的卡片轮廓，图案没有裁切。

### 启动器层

- 必须在 `emulator-5554` API 35 查看系统应用信息页与 Pixel Launcher。
- 真机授权时，必须在 OPPO Find N5 / ColorOS 桌面查看；不能用模拟器、导出图或构建成功替代。
- OPPO 截图只证明设备实际呈现。是否达到图标视觉要求仍以用户明确确认作为最终门禁。

## 7. 证据与变更边界

每次图标调整记录：母版哈希、背景/前景文件哈希、前景实际比例、构建 APK 哈希、测试设备与截图路径。不得提交用户桌面截图、临时合成图、真实个人数据或构建产物。

本规范是图标构建的唯一正文；架构治理、测试策略、交接和决策日志只记录当前状态并链接到这里。
