# Android 启动图标保真构建规范

## 1. 适用范围与唯一事实源

- 当前唯一母版是 `design/assets/app-icon-master.png`，SHA-256 为 `81d0c0bc46413543107c6b8a43edd2c994575945ef3ff4fdb6d6cb762b7030c0`。它是用户提供文件的逐字节副本，只读保存，不能以旧导出位图反向替代，也不能用生成式工具重绘。
- `design/assets/app-icon-master-alpha75.jpg` 仅归档上一版米色母版，不再参与构建。
- 本规范只规定 Android 图标包装，不改变母版的图案、色相、比例关系或阴影语言。
- `mipmap-*` 兼容资源必须把本规范的深蓝材质背景与原坐标前景扁平化导出；不能直接缩放带白画布的母版。Android 26+ 使用同一视觉的两层自适应资源。

## 2. 目标视觉

启动器中应当看见一张完整、留有呼吸空间的深蓝图标：深蓝材质从图案内部自然延展到系统蒙版边缘；米白环形、“南枫”、圆点和橙色枫叶完整可见。母版外侧白色画布与烘焙圆角只属于导出包装，不能进入 Android 图标。禁止出现白边、白色外框、额外卡片、被裁断的图案或被任意放大的满画布前景。

## 3. 分层构成

| 层 | 工程资源 | 必须满足 | 禁止做法 |
|---|---|---|---|
| 材质背景 | `drawable-nodpi/app_icon_background.png` | 1254×1254、全不透明；只从母版中不含图案的深蓝区域拟合原有明暗走势，生成连续材质场并延展至全画布 | 复用原图的白画布；填充固定单色；保留烘焙圆角卡片边界；把完整图案烙进背景 |
| 图案前景 | `drawable-nodpi/app_icon_source.png` | 1254×1254、透明底；只含原图的米白／橙色图案、抗锯齿和必要软阴影，保持母版画布坐标 | 把深蓝卡片、白画布或整张母版放进前景；以矢量/AI 重画图案；在构建后另行缩放前景 |

`mipmap-anydpi-v26/ic_launcher.xml` 与 `ic_launcher_round.xml` 必须继续只组合这两个层：背景指向 `app_icon_background`，前景指向 `app_icon_source`。

## 4. 当前母版的坐标与系统归一化基线

- 原始提取图案在用户 PNG 中 alpha>8 的可见边界为 `(210,155)–(1057,994)`，不裁切、不重排。
- Android Launcher 会对 adaptive foreground 做约 **4/3** 的二次归一化；若直接写入原坐标，真实 Launcher 会再次放大并裁切。当前前景必须在 1254×1254 透明画布内以中心为锚点预缩放至 **75%**，抵消该系统变换；补偿后的 alpha 可见边界不得超过画布宽高的 53%。
- 75% 是写入 `app_icon_source.png` 的实际包装补偿，不是改画，也不是只缩小本地预览。APK、legacy 合成和所有密度必须消费同一份补偿后前景。
- 母版白色外画布只用于原始导出展示；Android 由不透明深蓝背景延展替代，系统负责最终圆形、圆角方形等蒙版。
- 后续若目标启动器出现归一化差异，只能基于“补偿后前景 × 4/3 系统归一化”的等可见尺寸对照做可测量补偿，并重新生成全部资源；不能只改预览或单个密度。

## 5. 固定构建顺序

1. 校验母版路径、尺寸与哈希；不修改母版。
2. 从母版的非图案深蓝有效区域构建全画布连续材质背景，消除母版外侧白画布与原圆角卡片边缘。
3. 提取原图图案、金色细节和必要软阴影为透明前景；背景色像素不得随前景带入。
4. 将提取前景在 **前景 PNG 本身** 中按 75% 居中补偿；本地验收必须再模拟 Launcher 的 4/3 归一化后套用圆形／圆角方形蒙版，不能只看未归一化的 1:1 合成图。
5. 用同一份背景与实际比例前景导出 `mipmap-*` 兼容位图，并替换 Android 资源后构建 APK；不得把临时合成预览当成最终资源。
6. 使用 `scripts/build_android_launcher_icon.py` 从唯一母版一次生成两层资源与五档 legacy 资源；真实启动器覆盖安装后重新读取桌面图标，只在用户视觉确认后更新真机验收状态。

## 6. 不可省略的校验

### 文件层

- 背景与前景均为 1254×1254 PNG；背景 alpha 必须全为 255，前景必须存在透明区。
- 自适应 XML、Manifest 的 `icon` 与 `roundIcon` 路径保持完整；legacy 位图与 adaptive 合成图不得出现白画布；不新增网络权限或外部调用。
- 本地 1:1 合成图中，画布边缘不存在白色像素带或可辨的卡片轮廓，图案没有裁切。

### 启动器层

- 必须在 `emulator-5554` API 35 查看系统应用信息页与 Pixel Launcher。
- 真机授权时，必须在 OPPO Find N5 / ColorOS 桌面查看；不能用模拟器、导出图或构建成功替代。
- OPPO 截图只证明设备实际呈现。是否达到图标视觉要求仍以用户明确确认作为最终门禁。

## 7. 证据与变更边界

每次图标调整记录：母版哈希、背景/前景文件哈希、前景实际比例、构建 APK 哈希、测试设备与截图路径。不得提交用户桌面截图、临时合成图、真实个人数据或构建产物。

本规范是图标构建的唯一正文；架构治理、测试策略、交接和决策日志只记录当前状态并链接到这里。
